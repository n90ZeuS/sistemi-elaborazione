Il problema della crescita del codice

Perché serve un nuovo paradigma?

Approccio procedurale: dati e funzioni separati

studente_1: dict[str, str | int | list[int]] = {
    "nome": "Anna",
    "cognome": "Rossi",
    "matricola": 12345,
    "voti": [28, 30, 25, 27]
}

def calcola_media(studente: dict[str, str | int | list[int]]) -> float:
    voti: list[int] = studente["voti"]  # type: ignore
    return sum(voti) / len(voti)

def aggiungi_voto(studente: dict[str, str | int | list[int]],
                  voto: int) -> None:
    if not 18 <= voto <= 30:
        raise ValueError(f"Voto {voto} non valido")
    studente["voti"].append(voto)  # type: ignore
Questo è il punto di partenza: codice procedurale che funziona ma scala male.

I problemi concreti

  • Nessuna garanzia di struttura — nulla impedisce un dizionario senza la chiave "voti"
  • Funzioni scollegate dai dati — calcola_media potrebbe ricevere un dizionario qualsiasi
  • Tipo illeggibile — dict[str, str | int | list[int]] non dice "questo è uno studente"
  • Validazione non centralizzata — bisogna controllare la matricola in ogni funzione
La soluzione: unire stato (dati) e comportamento (funzioni) in un'unica entità chiamata oggetto.

Già usate oggetti

In Python, tutto è un oggetto

Oggetti che conoscete già

# Le stringhe sono oggetti
nome: str = "ciao"
print(nome.upper())       # "CIAO" — upper() è un metodo
print(nome.replace("c", "C"))  # "Ciao"

# Le liste sono oggetti
voti: list[int] = [28, 30, 25]
voti.append(27)            # append() è un metodo
voti.sort()                # sort() è un altro metodo

# Anche i numeri sono oggetti
n: int = 42
print(n.bit_length())     # 6 — quanti bit servono per 42
print((3.14).is_integer()) # False
Il punto (.) è l'operatore per accedere a metodi e attributi di un oggetto.

Tipi e classi

print(type(42))        # <class 'int'>
print(type("ciao"))    # <class 'str'>
print(type([1, 2, 3])) # <class 'list'>
La parola class nell'output ci dice che int, str e list sono classi.
Ogni valore concreto (42, "ciao", [1, 2, 3]) è un'istanza di quella classe.

Classi e istanze

Il modello e la realizzazione concreta

Classe = progetto, Istanza = oggetto concreto

La classe è il progetto architettonico di una casa.

L'istanza è una casa costruita seguendo quel progetto.

Da un unico progetto si possono costruire cento case, ciascuna con i propri abitanti.

La prima classe: Punto

# La classe è il progetto
class Punto:
    """Rappresenta un punto nel piano cartesiano."""

    def __init__(self, x: float, y: float) -> None:
        self.x: float = x
        self.y: float = y

# Le istanze sono i punti concreti
origine: Punto = Punto(0.0, 0.0)
p1: Punto = Punto(3.0, 4.0)
p2: Punto = Punto(-1.5, 2.7)

print(p1.x)  # 3.0 — accediamo all'attributo x dell'istanza p1
Ogni istanza ha i propri valori per x e y. Modificare p1.x non cambia p2.x.

Esempio completo: la classe Studente

Risolviamo il problema dell'introduzione

Definizione della classe Studente

class Studente:
    """Rappresenta uno studente universitario con i suoi esami."""

    universita: str = "Università degli Studi"  # Attributo di CLASSE

    def __init__(self, nome: str, cognome: str, matricola: int) -> None:
        if not nome.strip():
            raise ValueError("Il nome non può essere vuoto")
        if matricola <= 0:
            raise ValueError(f"Matricola non valida: {matricola}")

        self.nome: str = nome.strip()        # Attributi di ISTANZA
        self.cognome: str = cognome.strip()
        self.matricola: int = matricola
        self.voti: list[int] = []
Notare la validazione centralizzata nel costruttore: non è possibile creare uno studente malformato.

Metodi della classe Studente

    def aggiungi_voto(self, voto: int) -> None:
        """Aggiunge un voto alla carriera dello studente."""
        if not 18 <= voto <= 30:
            raise ValueError(f"Voto {voto} fuori dall'intervallo 18-30")
        self.voti.append(voto)

    def media(self) -> float:
        """Calcola la media aritmetica dei voti."""
        if not self.voti:
            raise ValueError("Nessun voto registrato")
        return sum(self.voti) / len(self.voti)

    def numero_esami(self) -> int:
        return len(self.voti)

    def descrizione(self) -> str:
        stato: str = f"media {self.media():.1f}" if self.voti else "nessun esame"
        return f"{self.nome} {self.cognome} (mat. {self.matricola}) — {stato}"

Uso della classe Studente

anna: Studente = Studente("Anna", "Rossi", 12345)
marco: Studente = Studente("Marco", "Bianchi", 67890)

anna.aggiungi_voto(28)
anna.aggiungi_voto(30)
anna.aggiungi_voto(25)

print(anna.descrizione())  # Anna Rossi (mat. 12345) — media 27.7
print(marco.media())       # ValueError: Nessun voto registrato

# La validazione funziona
anna.aggiungi_voto(35)  # ValueError: Voto 35 fuori dall'intervallo 18-30
Vantaggi rispetto al procedurale: tipo chiaro, validazione centralizzata, dati e comportamento uniti, supporto del type checker.

__init__ e self

Due concetti fondamentali

__init__: inizializzazione, non costruzione

Precisazione: __init__ non è il costruttore. Il vero costruttore è __new__, che crea l'oggetto in memoria. __init__ lo configura.

Quando scriviamo Studente("Anna", "Rossi", 12345), Python esegue:

  1. Crea un nuovo oggetto di tipo Studente (tramite __new__)
  2. Chiama __init__ passandogli quell'oggetto come primo argomento (self)

self: il riferimento esplicito

class Esempio:
    def saluta(self) -> str:
        return f"Sono l'oggetto {id(self)}"

e: Esempio = Esempio()
print(e.saluta())
# Sono l'oggetto 140234567890

# Python traduce internamente in:
# Esempio.saluta(e)
Zen di Python:
"Explicit is better than implicit."

A differenza di Java/C++ (this implicito), Python rende self esplicito.

Vantaggio: sempre chiaro cosa è self.nome (attributo) vs nome (variabile locale).

self non è una parola riservata, ma usare un nome diverso è un errore di stile grave.

Attributi di istanza vs di classe

Due tipi di attributi, da non confondere

Attributi di istanza

Definiti con self.nome_attributo dentro __init__. Ogni istanza ha la propria copia.

class Contatore:
    def __init__(self) -> None:
        self.valore: int = 0  # Attributo di istanza

    def incrementa(self) -> None:
        self.valore += 1

c1: Contatore = Contatore()
c2: Contatore = Contatore()
c1.incrementa()
c1.incrementa()

print(c1.valore)  # 2
print(c2.valore)  # 0 — c2 è indipendente da c1

Attributi di classe

Definiti nel corpo della classe, fuori dai metodi. Condivisi da tutte le istanze.

class Studente:
    universita: str = "Università degli Studi"  # Attr. di classe
    _contatore: int = 0

    def __init__(self, nome: str) -> None:
        self.nome: str = nome           # Attr. di istanza
        Studente._contatore += 1
        self.numero: int = Studente._contatore

s1: Studente = Studente("Anna")
s2: Studente = Studente("Marco")
print(Studente.universita)   # "Università degli Studi"
print(Studente._contatore)   # 2
Utili per costanti condivise o contatori globali. Usateli con parsimonia.

Confronto rapido

Attributo di istanza Attributo di classe
Dove Dentro __init__ con self. Nel corpo della classe
Condivisione Ogni istanza ha la propria copia Condiviso tra tutte le istanze
Accesso self.attributo Classe.attributo
Uso tipico Dati specifici dell'oggetto Costanti, contatori globali

Metodi speciali

I dunder methods: integrazione con il linguaggio

__str__ e __repr__

class Punto:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Punto(3.0, 4.0)
print(p)
# <__main__.Punto object
#  at 0x...>
class Punto:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __str__(self):
        return f"({self.x}, {self.y})"
    def __repr__(self):
        return f"Punto(x={self.x}, y={self.y})"

p = Punto(3.0, 4.0)
print(p)    # (3.0, 4.0)
repr(p)     # Punto(x=3.0, y=4.0)
__str__ = leggibile per gli umani. __repr__ = tecnica, per i programmatori.
Se ne definite uno solo, scegliete __repr__: Python lo usa come fallback.

__len__ e __getitem__

__len__

class Classe:
    def __init__(self, nome: str):
        self.nome = nome
        self.studenti: list[str] = []

    def aggiungi(self, s: str):
        self.studenti.append(s)

    def __len__(self) -> int:
        return len(self.studenti)

c = Classe("1A")
c.aggiungi("Anna")
c.aggiungi("Marco")
print(len(c))  # 2

__getitem__

class SerieStorica:
    def __init__(self, valori: list[float]):
        self.valori = valori

    def __getitem__(self, i: int):
        return self.valori[i]

    def __len__(self) -> int:
        return len(self.valori)

serie = SerieStorica([100, 102.5, 98.3])
print(serie[0])   # 100.0
print(serie[-1])  # 98.3

__eq__ e __lt__: confronti

class Punto:
    def __init__(self, x: float, y: float) -> None:
        self.x, self.y = x, y

    def __eq__(self, altro: object) -> bool:
        if not isinstance(altro, Punto):
            return NotImplemented
        return self.x == altro.x and self.y == altro.y

    def __lt__(self, altro: "Punto") -> bool:
        """Ordina per distanza dall'origine."""
        return (self.x ** 2 + self.y ** 2) < (altro.x ** 2 + altro.y ** 2)

p1: Punto = Punto(3.0, 4.0)
p2: Punto = Punto(3.0, 4.0)
print(p1 == p2)  # True  — stesse coordinate
print(p1 is p2)  # False — oggetti diversi in memoria
Attenzione: in __eq__ si restituisce NotImplemented (non NotImplementedError!) se il tipo non corrisponde.

Riepilogo dei metodi speciali

Metodo Invocato da Scopo
__init__ Classe(...) Inizializzazione
__str__ str(obj), print(obj) Rappresentazione leggibile
__repr__ repr(obj), nel REPL Rappresentazione tecnica
__len__ len(obj) Lunghezza
__eq__ obj1 == obj2 Uguaglianza
__lt__ obj1 < obj2, sorted() Confronto "minore di"
__getitem__ obj[i] Accesso per indice
__contains__ x in obj Appartenenza
__add__ obj1 + obj2 Somma
__bool__ if obj: Valore di verità

Ereditarietà

Creare nuove classi basate su classi esistenti

La relazione "è un" (is-a)

Uno StudenteLavoratore è uno Studente con caratteristiche in più.

Superclasse: Studente

class Studente:
    """Studente universitario."""

    def __init__(self, nome: str, cognome: str, matricola: int) -> None:
        self.nome: str = nome
        self.cognome: str = cognome
        self.matricola: int = matricola
        self.voti: list[int] = []

    def aggiungi_voto(self, voto: int) -> None:
        if not 18 <= voto <= 30:
            raise ValueError(f"Voto {voto} fuori dall'intervallo 18-30")
        self.voti.append(voto)

    def media(self) -> float:
        if not self.voti:
            raise ValueError("Nessun voto registrato")
        return sum(self.voti) / len(self.voti)

    def __str__(self) -> str:
        return f"{self.nome} {self.cognome} (mat. {self.matricola})"

Sottoclasse: StudenteLavoratore

class StudenteLavoratore(Studente):
    """Studente che lavora part-time."""

    def __init__(self, nome: str, cognome: str, matricola: int,
                 azienda: str, ore_settimanali: int) -> None:
        super().__init__(nome, cognome, matricola)  # Chiama il __init__ madre
        self.azienda: str = azienda
        self.ore_settimanali: int = ore_settimanali

    def è_part_time(self) -> bool:
        return self.ore_settimanali < 20

    def __str__(self) -> str:
        base: str = super().__str__()
        return f"{base} — lavora presso {self.azienda} ({self.ore_settimanali}h/sett.)"
super() restituisce un riferimento alla superclasse, per riutilizzarne il codice senza duplicazione.

Uso della sottoclasse

sl: StudenteLavoratore = StudenteLavoratore(
    "Giulia", "Verdi", 11111, "DataCorp", 16
)

# Metodi ereditati da Studente
sl.aggiungi_voto(28)
sl.aggiungi_voto(30)
print(sl.media())       # 29.0

# Metodi propri di StudenteLavoratore
print(sl.è_part_time()) # True

# __str__ ridefinito
print(sl)  # Giulia Verdi (mat. 11111) — lavora presso DataCorp (16h/sett.)

# isinstance funziona con l'ereditarietà
print(isinstance(sl, StudenteLavoratore))  # True
print(isinstance(sl, Studente))            # True

"È un" vs "ha un": composizione

# Dipartimento NON è una lista
class Dipartimento(list):
    pass

Ereditarietà sbagliata: un Dipartimento non "è una" lista

# Dipartimento HA una lista
class Dipartimento:
    def __init__(self, nome: str):
        self.nome = nome
        self.docenti: list[Docente] = []

    def aggiungi_docente(self, d):
        self.docenti.append(d)

Composizione: il Dipartimento contiene docenti come attributo

"Preferire la composizione all'ereditarietà."
L'ereditarietà crea accoppiamento forte. La composizione è più flessibile.

Incapsulamento e @property

Controllare l'accesso agli attributi

La convenzione dell'underscore

class ContoBancario:
    def __init__(self, titolare: str, saldo_iniziale: float = 0.0) -> None:
        self.titolare: str = titolare
        self._saldo: float = saldo_iniziale  # _ = uso interno

    def deposita(self, importo: float) -> None:
        if importo <= 0:
            raise ValueError("L'importo deve essere positivo")
        self._saldo += importo

    def preleva(self, importo: float) -> None:
        if importo <= 0:
            raise ValueError("L'importo deve essere positivo")
        if importo > self._saldo:
            raise ValueError("Saldo insufficiente")
        self._saldo -= importo
L'underscore _ è una convenzione, non un divieto tecnico: "non accedere direttamente a _saldo da fuori la classe".

Il decoratore @property

class ContoBancario:
    def __init__(self, titolare: str, saldo_iniziale: float = 0.0) -> None:
        self.titolare: str = titolare
        self._saldo: float = saldo_iniziale

    @property
    def saldo(self) -> float:
        """Il saldo corrente (sola lettura)."""
        return self._saldo

    def deposita(self, importo: float) -> None:
        if importo <= 0:
            raise ValueError("L'importo deve essere positivo")
        self._saldo += importo
conto: ContoBancario = ContoBancario("Anna Rossi", 1000.0)
print(conto.saldo)   # 1000.0 — sembra un attributo, ma è un metodo!
conto.deposita(500)
print(conto.saldo)   # 1500.0

conto.saldo = 9999   # AttributeError: property 'saldo' has no setter
@property permette di aggiungere logica (validazione, log, conversioni) senza cambiare l'interfaccia esterna.

Collegamento con il mondo dei dati

Lo state già usando nelle librerie scientifiche

pandas DataFrame

df: pd.DataFrame = pd.DataFrame({

scikit-learn: modelli come oggetti

from sklearn.linear_model import LinearRegression
import numpy as np

modello: LinearRegression = LinearRegression()       # Istanza
X: np.ndarray = np.array([[1], [2], [3], [4]])
y: np.ndarray = np.array([2.1, 3.9, 6.2, 7.8])

modello.fit(X, y)                         # Metodo: addestra
previsioni = modello.predict(X)           # Metodo: predice
print(modello.coef_)                      # Attributo: coefficienti
print(modello.intercept_)                 # Attributo: intercetta
Consistenza: tutti i modelli scikit-learn (regressione, alberi, reti neurali) seguono la stessa interfaccia .fit() / .predict() grazie all'ereditarietà.

Riepilogo

I concetti fondamentali da portare con sé

Concetti chiave

  1. Classe = modello, istanza = oggetto concreto.
    La classe definisce la struttura; le istanze contengono i dati.
  2. self è esplicito.
    Ogni metodo riceve il riferimento all'istanza come primo argomento.
  3. I metodi speciali integrano gli oggetti nel linguaggio.
    __str__, __repr__, __len__, __eq__ rendono i vostri oggetti cittadini di prima classe.
  4. Preferite la composizione all'ereditarietà.
    "È un" → ereditarietà. "Ha un" → composizione.
  5. Tutto in Python è un oggetto.
    Stringhe, liste, DataFrame, modelli ML — tutto segue gli stessi principi.

Quando usare una classe?

Python è multi-paradigma: potete mescolare funzioni, classi e moduli.

Usate una classe se:

  • Avete dati e comportamento che vanno insieme
  • Serve validazione centralizzata
  • Volete un tipo chiaro e riutilizzabile

Lasciate una funzione se:

  • Non serve stato interno
  • La logica è semplice e autonoma
  • Non avete bisogno di più istanze
Non tutto deve essere una classe. La regola è pragmatica, non dogmatica.
