1. Funzioni come oggetti
di prima classe

Le funzioni sono dati, come numeri e stringhe

Funzioni = Oggetti

In Python, ogni funzione e un oggetto: ha un tipo (function), occupa memoria e puo essere trattata come qualsiasi altro dato.

Cosa significa in pratica?

  • Si puo assegnare a una variabile
  • Si puo passare come argomento a un'altra funzione
  • Si puo restituire come risultato di un'altra funzione
Questo concetto si chiama "funzioni come cittadini di prima classe" (first-class citizens). Non tutti i linguaggi lo supportano nativamente.

Assegnare una funzione a una variabile

Il nome della funzione senza parentesi e un riferimento all'oggetto:

def quadrato(x: float) -> float:
    return x ** 2

# Assegniamo la funzione (non il risultato!) a una variabile
operazione: callable = quadrato

print(operazione(5))    # 25
print(type(operazione)) # <class 'function'>
Attenzione: quadrato e l'oggetto funzione, quadrato(5) e il risultato dell'invocazione.

Passare una funzione come argomento

Una funzione che riceve un'altra funzione si chiama funzione di ordine superiore (higher-order function).

def applica_a_lista(f: callable, valori: list[float]) -> list[float]:
    """Applica la funzione f a ogni elemento della lista."""
    risultati: list[float] = []
    for v in valori:
        risultati.append(f(v))
    return risultati

numeri: list[float] = [4.0, 9.0, 16.0, 25.0]

print(applica_a_lista(quadrato, numeri))
# [16.0, 81.0, 256.0, 625.0]
applica_a_lista non sa quale funzione ricevera: sa solo che ne ricevera una. Questo rende il codice generico e riusabile.

Restituire una funzione

Le funzioni possono creare e restituire altre funzioni:

def crea_moltiplicatore(fattore: float) -> callable:
    """Restituisce una funzione che moltiplica per il fattore dato."""
    def moltiplicatore(x: float) -> float:
        return x * fattore
    return moltiplicatore

doppio: callable = crea_moltiplicatore(2)
triplo: callable = crea_moltiplicatore(3)

print(doppio(10))  # 20
print(triplo(10))  # 30
Closure: la funzione interna "ricorda" il valore di fattore anche dopo che crea_moltiplicatore ha terminato l'esecuzione.

2. Funzioni lambda

Funzioni anonime per operazioni brevi

Sintassi delle lambda

lambda parametri: espressione

Una lambda e una funzione che:

  • Non ha nome (e anonima)
  • Contiene una sola espressione
  • Restituisce automaticamente il risultato
# Lambda che calcola il quadrato
quadrato_lambda = lambda x: x ** 2
print(quadrato_lambda(5))  # 25

# Lambda con piu parametri
somma = lambda a, b: a + b
print(somma(3, 7))  # 10

Equivalenza lambda / def

Lambda assegnata a variabile

media = lambda valori: sum(valori) / len(valori)

Funzione con def

def media(valori: list[float]) -> float:
    return sum(valori) / len(valori)
Regola: assegnare una lambda a una variabile e cattivo stile. Se la funzione ha bisogno di un nome, usate def.

Quando usare le lambda

Si: argomento inline

nomi = ["Marco", "Anna", "Giulia", "Bo"]
ordinati = sorted(nomi, key=lambda s: len(s))

No: logica complessa

  • Se serve piu di una riga
  • Se serve un nome descrittivo
  • Se servono istruzioni (for, while, try)
Regola pratica: usate lambda quando la funzione e cosi breve e ovvia che darle un nome la renderebbe meno leggibile.

3. sorted() con key=

Un pattern potentissimo per l'analisi dati

Come funziona key

Il parametro key accetta una funzione applicata a ogni elemento prima del confronto:

parole: list[str] = ["Python", "e", "fantastico", "e", "potente"]

# Ordinamento lessicografico (default)
print(sorted(parole))
# ['Python', 'e', 'fantastico', 'potente', 'e']

# Ordinamento per lunghezza
print(sorted(parole, key=lambda s: len(s)))
# ['e', 'e', 'Python', 'potente', 'fantastico']
L'ordinamento avviene sui valori restituiti da key, ma la lista risultante contiene gli elementi originali.

Ordinare strutture complesse

studenti: list[dict] = [
    {"nome": "Anna",   "media": 28.5},
    {"nome": "Marco",  "media": 24.0},
    {"nome": "Giulia", "media": 30.0},
    {"nome": "Luca",   "media": 26.5},
]

# Ordinare per media (crescente)
per_media = sorted(studenti, key=lambda s: s["media"])

# Ordinare per media (decrescente)
per_media_desc = sorted(
    studenti, key=lambda s: s["media"], reverse=True
)
Questo pattern e comunissimo nell'analisi dati: liste di dizionari che rappresentano record da ordinare per un campo specifico.

Ordinare per piu criteri

Basta restituire una tupla dalla funzione key:

esami: list[dict] = [
    {"materia": "Statistica",   "voto": 28, "data": "2025-06-15"},
    {"materia": "Informatica",  "voto": 30, "data": "2025-06-10"},
    {"materia": "Matematica",   "voto": 28, "data": "2025-07-01"},
]

# Prima per voto (decrescente), poi per data (crescente)
ordinati = sorted(esami, key=lambda e: (-e["voto"], e["data"]))
Trucco: il segno meno -e["voto"] inverte l'ordine solo per quel criterio.

min() e max() con key

Lo stesso parametro key funziona anche con min() e max():

studenti: list[dict] = [
    {"nome": "Anna",   "media": 28.5},
    {"nome": "Marco",  "media": 24.0},
    {"nome": "Giulia", "media": 30.0},
    {"nome": "Luca",   "media": 26.5},
]

# Studente con la media piu alta
migliore = max(studenti, key=lambda s: s["media"])
print(migliore["nome"])  # Giulia

# Studente con la media piu bassa
peggiore = min(studenti, key=lambda s: s["media"])
print(peggiore["nome"])  # Marco

4. map() e filter()

Strumenti di programmazione funzionale

map() — Applicare una funzione a tutti

voti: list[int] = [25, 28, 30, 22, 27]

# Convertire i voti in scala 0-100
voti_percentuale = list(map(lambda v: v / 30 * 100, voti))
print(voti_percentuale)  # [83.33, 93.33, 100.0, 73.33, 90.0]
map(f, iterabile) → iteratore

[25, 28, 30, 22, 27]
↓   ↓   ↓   ↓   ↓   f(x) = x/30*100
[83.3, 93.3, 100.0, 73.3, 90.0]
map restituisce un iteratore, non una lista. Va avvolto in list() se si vuole una lista.

filter() — Selezionare elementi

voti: list[int] = [25, 28, 30, 22, 27, 18, 31]

# Solo voti sufficienti (>= 18) e validi (<= 30)
validi = list(filter(lambda v: 18 <= v <= 30, voti))
print(validi)  # [25, 28, 30, 22, 27, 18]
filter(f, iterabile) → elementi dove f restituisce True

[25, 28, 30, 22, 27, 18, 31]
↓   ↓   ↓   ↓   ↓   ↓   ✗
[25, 28, 30, 22, 27, 18]

map/filter vs list comprehension

Comprehension

# map equivalente
[v / 30 * 100 for v in voti]

# filter equivalente
[v for v in voti if 18 <= v <= 30]

# map + filter combinati
[v / 30 * 100 for v in voti
 if 18 <= v <= 30]

map/filter

# Con funzione esistente: pulito
numeri_stringa = ["1", "2", "3"]
numeri = list(map(int, numeri_stringa))

# Equivalente comprehension
numeri = [int(s)
          for s in numeri_stringa]
Regola: se avete una funzione con un nome, map() e spesso piu conciso; se serve una lambda, la comprehension e quasi sempre piu chiara.

5. Moduli e import

Organizzare il codice in piu file

Cos'e un modulo

In Python, ogni file .py e un modulo.

Un modulo contiene definizioni (funzioni, classi, variabili) che possono essere importate da altri file.

# statistiche.py
def media(valori: list[float]) -> float:
    """Calcola la media aritmetica."""
    return sum(valori) / len(valori)

def varianza(valori: list[float]) -> float:
    """Calcola la varianza campionaria."""
    m: float = media(valori)
    return sum((x - m) ** 2 for x in valori) / (len(valori) - 1)

Forme di import

# 1. Import del modulo intero
import statistiche
risultato = statistiche.media([1, 2, 3, 4, 5])

# 2. From ... import: nomi specifici
from statistiche import media, varianza
risultato = media([1, 2, 3, 4, 5])

# 3. Alias con as
import statistiche as stat
risultato = stat.media([1, 2, 3, 4, 5])
Da evitare sempre: from statistiche import *
Importa TUTTO, inquinando il namespace. Se due moduli definiscono lo stesso nome, l'ultimo sovrascrive senza avvertimenti.

Confronto tra le forme di import

Forma Vantaggi Svantaggi
import modulo Esplicito, tracciabile Nomi lunghi
from modulo import nome Conciso Origine meno chiara
import modulo as alias Compatto e chiaro Alias da ricordare
from modulo import * Nessuno Pericoloso, non tracciabile

Alias convenzionali: import numpy as np, import pandas as pd

6. La libreria standard

"Batteries included"

Batteries included

Python viene distribuito con una libreria standard vastissima: centinaia di moduli pronti all'uso, senza installare nulla.

Moduli che vedremo oggi:

  • math matematica
  • statistics statistica
  • random simulazione
  • csv dati
  • json dati
  • datetime date
  • collections strutture

math — Funzioni matematiche

import math

print(math.sqrt(16))       # 4.0
print(math.log(100, 10))   # 2.0 (logaritmo in base 10)
print(math.log(math.e))    # 1.0 (logaritmo naturale)
print(math.pi)             # 3.141592653589793
print(math.factorial(5))   # 120
print(math.ceil(3.2))      # 4
print(math.floor(3.8))     # 3

statistics — Statistica descrittiva

import statistics

dati: list[float] = [2.5, 3.1, 2.8, 3.5, 2.9, 3.3, 3.0]

print(statistics.mean(dati))      # 3.014...
print(statistics.median(dati))    # 3.0
print(statistics.stdev(dati))     # 0.329...  (dev. std campionaria)
print(statistics.variance(dati))  # 0.108...  (varianza campionaria)
print(statistics.mode([1, 2, 2, 3, 3, 3]))  # 3
Perfetto per calcoli statistici di base. Per analisi avanzate: numpy e scipy.

random — Numeri casuali

import random

random.seed(42)  # Riproducibilita!

print(random.random())              # Float in [0, 1)
print(random.randint(1, 100))       # Intero in [1, 100]
print(random.uniform(0.0, 10.0))    # Float in [0, 10]

nomi: list[str] = ["Anna", "Marco", "Giulia", "Luca"]
print(random.choice(nomi))          # Elemento casuale
print(random.sample(nomi, 2))       # 2 elementi senza ripetizione

random.shuffle(nomi)                # Mescola in-place
Per la statistica: random.seed() fissa il generatore pseudocasuale, rendendo le analisi riproducibili.

csv e json — Leggere dati

csv

import csv

with open("dati.csv", "r",
          encoding="utf-8") as f:
    lettore = csv.DictReader(f)
    for riga in lettore:
        print(riga["nome"],
              riga["voto"])

json

import json

testo = '{"nome": "Anna", "eta": 20}'
dati = json.loads(testo)
print(dati["nome"])  # Anna

output = json.dumps(
    dati, indent=2,
    ensure_ascii=False

datetime e collections

datetime

from datetime import date, timedelta

oggi = date.today()
tra_7gg = oggi + timedelta(days=7)

nascita = date(2005, 6, 15)
eta = oggi - nascita
print(f"Giorni: {eta.days}")

collections.Counter

from collections import Counter

voti = [28, 30, 28, 25, 30, 30, 27, 28]
freq = Counter(voti)
print(freq)
# Counter({30: 3, 28: 3, 25: 1, 27: 1})
print(freq.most_common(2))
# [(30, 3), (28, 3)]

collections.defaultdict

Un dizionario che crea automaticamente il valore di default per chiavi nuove:

from collections import defaultdict

studenti_per_corso: defaultdict[str, list[str]] = defaultdict(list)
studenti_per_corso["Statistica"].append("Anna")
studenti_per_corso["Statistica"].append("Marco")
studenti_per_corso["Informatica"].append("Giulia")

print(dict(studenti_per_corso))
# {'Statistica': ['Anna', 'Marco'], 'Informatica': ['Giulia']}
Niente piu controlli if chiave not in dizionario prima di aggiungere elementi.

8. Virtual environment

Isolamento e riproducibilita

Il problema

Progetto A → pandas 1.5
Progetto B → pandas 2.2

Python di sistema: una sola versione alla volta!
  • Installare pandas 2.2 rompe il Progetto A
  • Reinstallare pandas 1.5 rompe il Progetto B
  • Collaborare con colleghi che hanno versioni diverse

La soluzione: venv

Un virtual environment e una copia isolata dell'interprete Python con i propri pacchetti, separata dal sistema e dagli altri ambienti. 
# Creare un ambiente virtuale (una sola volta)
python -m venv .venv

# Attivare (ogni volta che si lavora al progetto)
# macOS/Linux:
source .venv/bin/activate
# Windows:
.venv\Scripts\activate

# Il prompt cambia:
(.venv) $ pip install numpy   # installa solo in .venv/

# Disattivare
deactivate

requirements.txt

Per garantire la riproducibilita:

Generare

pip freeze > requirements.txt

Produce un file come:

numpy==1.26.4
pandas==2.2.0
matplotlib==3.8.2

Ricreare l'ambiente

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
Stesse versioni = stessi risultati.

Workflow completo

1. python -m venv .venv
↓
2. source .venv/bin/activate
↓
3. pip install numpy pandas matplotlib
↓
4. ... scrivi codice ...
↓
5. pip freeze > requirements.txt
↓
6. git add requirements.txt
↓
7. deactivate
Convenzione: .venv e il nome standard. Il punto iniziale lo rende nascosto. I .gitignore standard gia lo escludono.

9. Best practice per gli import

Ordine, leggibilita, manutenibilita

Ordine degli import (PEP 8)

Tre gruppi, separati da una riga vuota:

# 1. Libreria standard
import math
import statistics
from collections import Counter
from datetime import date

# 2. Pacchetti di terze parti (installati con pip)
import numpy as np
import pandas as pd

# 3. Moduli propri del progetto
from mio_progetto.utils import pulisci_dati
from mio_progetto.modelli import regressione
Posizione: sempre all'inizio del file, subito dopo la docstring del modulo.

Un import per riga

import math
import statistics
import random
import math, statistics, random

Eccezione: con from ... import e accettabile importare piu nomi:

from datetime import date, datetime, timedelta
Importate solo cio che usate. Un import inutilizzato e rumore. VS Code e PyCharm li segnalano automaticamente.
