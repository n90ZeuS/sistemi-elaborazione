Perché serve un
sistema operativo

Il direttore d'orchestra del computer

Il problema

Abbiamo costruito un elaboratore: CPU, memoria, bus, dispositivi.

Ma se lo accendete ora… non succede nulla.

Manca il software di sistema — nessuno gestisce le risorse, coordina i programmi, vi permette di interagire con la macchina.

Il sistema operativo è il programma più importante che non vedrete mai: lavora silenziosamente sotto ogni cosa che fate al computer.

Analogia: un'orchestra con 100 musicisti, senza direttore. Caos totale.

L'analogia dell'orchestra

Direttore d'orchestra = Sistema Operativo
Musicisti = Programmi
Strumenti = Risorse hardware (CPU, RAM, disco, rete)
Spartito = Istruzioni da eseguire

Il direttore garantisce che tutto funzioni armoniosamente: chi suona quando, chi aspetta chi, come gestire un solo pianoforte con tre pianisti.

Le 4 funzioni fondamentali

1. Astrazione dell'hardware

Nasconde la complessità dietro interfacce uniformi

2. Gestione delle risorse

Assegna CPU, memoria, disco ai programmi

3. Interfaccia utente

Terminale, finestre, touch screen

4. Sicurezza e protezione

Isolamento tra processi, permessi di accesso

Astrazione dell'hardware

L'hardware è complesso e diversificato: centinaia di modelli di dischi, schede di rete, schermi.

Il SO li nasconde dietro un'interfaccia uniforme.

# Non dovete sapere se il file è su SSD Samsung o HDD Seagate,
# se usa NTFS o ext4. Il SO se ne occupa.
open("dati.csv")
Risultato: scrivete lo stesso codice indipendentemente dall'hardware sottostante.

Gestione risorse e protezione

Gestione delle risorse

  • La CPU è una (o poche)
  • La RAM è limitata
  • Il disco è condiviso
  • Ma voi volete: browser + Spotify + VS Code + Python

Sicurezza e protezione

  • Ogni programma vive in uno spazio isolato
  • Non può accedere alla memoria altrui
  • Non può scrivere file senza permessi
  • Un bug non distrugge il sistema

Breve storia dei
sistemi operativi

Dalle schede perforate a Linux

L'era batch (anni '50–'60)

  • Programmi scritti su schede perforate
  • Consegnate a un operatore la mattina
  • Risultati ritirati il giorno dopo (se tutto andava bene)
  • Nessuna interazione con la macchina
I primi SO automatizzavano il processo: caricare un programma, eseguirlo, passare al successivo. Sistemi batch = elaborazione a lotti.

Il time-sharing (anni '60–'70)

Idea rivoluzionaria: suddividere il tempo della CPU tra molti utenti, dando a ciascuno l'illusione di avere il computer tutto per sé.

Multics (1964–69): MIT + Bell Labs + General Electric

Straordinariamente avanzato ma enormemente complesso.

Unix (1969)

Quando Bell Labs abbandonò Multics, Ken Thompson e Dennis Ritchie presero le idee migliori e le semplificarono radicalmente.

Principi fondamentali di Unix

  • "Fare una cosa sola e farla bene" — strumenti semplici combinati tramite pipe
  • "Tutto è un file" — interfaccia uniforme e composibile
  • Portabilità — riscritto in C nel 1973, indipendente dalla macchina

Da Unix discendono: BSD, Solaris, macOS, Linux, Android.

L'era dei personal computer

Sistema Anno Caratteristiche
MS-DOS 1981 Testuale, un solo programma alla volta
Windows 1985+ Interfaccia grafica, oggi ~72% desktop
Macintosh 1984 GUI con mouse e icone (ispirata da Xerox PARC)
Nota: macOS è, sotto la superficie, un sistema Unix (kernel derivato da BSD).

Linux (1991)

Linus Torvalds, studente finlandese di 21 anni:

"Sto facendo un sistema operativo (gratis) (solo un hobby, non sarà grande e professionale come gnu)"

Quel "hobby" oggi:

  • 96% dei server mondiali (Google, Amazon, Facebook)
  • Tutti i primi 500 supercomputer
  • Base di Android (3+ miliardi di dispositivi)
  • Spina dorsale del cloud computing
Il modello open-source: codice pubblico, chiunque contribuisce. Gratuito, robusto, flessibile, trasparente. Per un ricercatore, il software ispezionabile e verificabile ha un valore enorme.

Panorama attuale dei SO

Desktop

  • Windows ~72%
  • macOS ~16%
  • Linux ~4%

Server / Cloud

  • Linux ~96%
  • Windows Server ~4%

Mobile

  • Android (Linux) ~72%
  • iOS (Unix) ~27%
Osservazione: la filosofia Unix domina quasi ovunque, tranne il desktop.

Gestione dei processi

Come il SO esegue molti programmi contemporaneamente

Cos'è un processo

Quando eseguite un programma Python, il SO crea un processo: un'istanza del programma in esecuzione.

Ogni processo ha:

  • Spazio di indirizzamento privato
  • Stato (in esecuzione, in attesa, terminato)
  • PID — identificatore univoco
  • Risorse associate (file, connessioni)
Lo stesso programma può generare più processi indipendenti: due terminali con due script Python diversi = due processi distinti.

Multitasking e scheduling

8 core, ma decine di processi attivi. Come funziona?

Scheduling: il SO assegna brevi "fette di tempo" (time slice) sulla CPU, tipicamente pochi millisecondi. Il processore salta da un processo all'altro così velocemente che sembra tutto simultaneo.

Questo si chiama multitasking preemptivo: è il SO a decidere quando interrompere un processo, non il processo stesso.

Algoritmi di scheduling

Round-robin

Ogni processo riceve la stessa fetta di tempo, a turno, in ordine circolare.

Con priorità

TipoPriorità
Interfaccia graficaAlta
Audio/VideoMedia
Calcolo pesanteBassa

I processi interattivi hanno priorità alta per garantire reattività.

Thread e concorrenza

Un thread è un'unità di esecuzione all'interno di un processo.

  • Più leggeri dei processi
  • Condividono la memoria del processo
  • Vantaggio: comunicazione veloce
  • Rischio: race condition — due thread modificano lo stesso dato contemporaneamente

Python e il GIL

GIL (Global Interpreter Lock): un blocco che impedisce a più thread Python di eseguire bytecode contemporaneamente. 
import threading
# I thread NON girano
# in parallelo per
# codice Python puro
import multiprocessing
# Processi separati:
# vero parallelismo!
# (oppure NumPy, che usa C)
In pratica: per calcolo parallelo in Python, usate multiprocessing o librerie come NumPy che eseguono codice C/Fortran in parallelo.

Gestione della memoria

L'illusione di memoria infinita

Memoria virtuale

Ogni processo "crede" di avere un enorme spazio di memoria tutto per sé.

Dal punto di vista del processo

Memoria continua da 0 a 256 TB (64 bit)

In realtà

La RAM fisica è condivisa tra tutti i processi

La traduzione è trasparente: il programma non sa dove i suoi dati risiedono fisicamente.

Paginazione

  • Memoria virtuale divisa in pagine (4 KB tipicamente)
  • RAM fisica divisa in frame (stessa dimensione)
  • Il SO mantiene una tabella di traduzione: pagina → frame
  • Le pagine non usate possono essere spostate su disco (swap)
Page fault: quando il processo accede a una pagina non in RAM, il SO la carica dal disco. Tutto avviene automaticamente.

Perché il computer rallenta

Quando la RAM è satura:

RAM piena → Pagine spostate su disco continuamente → Thrashing

Disco: ~1000x più lento della RAM
Thrashing: il SO passa più tempo a spostare pagine che a eseguire programmi. Il computer diventa inutilizzabile. 
# Il famoso errore:
MemoryError
# Il processo ha richiesto più memoria di quanta il SO
# sia disposto ad allocargli.
Consiglio pratico: chiudete i programmi che non usate, specialmente il browser con molte schede aperte.

Il file system

Come il SO organizza i dati sul disco

Organizzazione logica

Due astrazioni fondamentali

File: contenitore di dati con un nome (documento, immagine, programma, dataset CSV)
Directory (cartella): contenitore di file e altre directory → struttura gerarchica ad albero

Metadati: nome, dimensione, data di creazione, data di modifica, permessi (chi può leggere, scrivere, eseguire).

Percorsi assoluti e relativi

Percorso assoluto

Parte dalla radice del file system

# Unix/macOS (radice: /)
/home/nicola/dati/studenti.csv

# Windows (radice: C:\)
C:\Users\nicola\dati\studenti.csv

Percorso relativo

Parte dalla directory corrente

# Se siete in /home/nicola/
dati/studenti.csv

# Tornare indietro
../altro_utente/file.txt
Attenzione: Unix usa /, Windows usa \. In Python usate pathlib: 
from pathlib import Path
Path("dati") / "studenti.csv"  # Funziona su entrambi!

File system a confronto

File System Sistema Caratteristiche
NTFS Windows Permessi, crittografia, file grandi
ext4 Linux Robusto, efficiente, ben collaudato
APFS macOS/iOS Ottimizzato per SSD, crittografia nativa
FAT32/exFAT Universale Chiavette USB; FAT32: limite 4 GB/file
Le chiavette USB usano FAT32 o exFAT per compatibilità universale: funzionano su Windows, macOS e Linux.

Reti e internet

Come i computer comunicano tra loro

Il modello a livelli

La comunicazione di rete è organizzata a livelli, ciascuno con una responsabilità specifica.

Ogni livello "incapsula" il messaggio del livello superiore.

TCP/IP

Il protocollo fondamentale di internet.

IP Internet Protocol

Instradamento: ogni dispositivo ha un indirizzo IP (es: 192.168.1.100). IP trova la strada per far arrivare i pacchetti a destinazione.

TCP Transmission Control

Affidabilità: garantisce che i dati arrivino completi, nell'ordine giusto, senza errori. Se un pacchetto si perde, lo ritrasmette.

HTTP e il World Wide Web

HTTP = HyperText Transfer Protocol
Il protocollo che fa funzionare il web
HTTPS = HTTP + crittografia
Dati cifrati, privacy protetta
Internet ≠ World Wide Web. Internet è l'infrastruttura (cavi, router, TCP/IP, dal 1969). Il Web è un servizio sopra internet (pagine + link, Tim Berners-Lee, CERN, 1989).

Cloud computing

Il "cloud" non è una nuvola magica: sono i computer di qualcun altro, in enormi data center.

Livello Sigla Cosa vi danno Esempio
Infrastructure IaaS Macchine virtuali AWS EC2, Google Compute
Platform PaaS Ambiente pronto Heroku, Google App Engine
Software SaaS Applicazione completa Gmail, Google Docs, Dropbox
Google Colab = il vostro codice Python gira su un server Google, non sul vostro computer.

API: i programmi parlano tra loro

Le API (Application Programming Interface) permettono ai programmi di comunicare.

# Esempio: scaricare dati da un'API pubblica
import requests

risposta = requests.get("https://api.istat.it/dati/popolazione")
dati = risposta.json()  # Risposta in formato JSON

# Dati pronti per l'analisi!
import pandas as pd
df = pd.DataFrame(dati)
Per lo statistico: le API permettono di raccogliere dati in modo automatizzato, riproducibile e aggiornato, senza scaricare file manualmente.

Concetti chiave

1. L'astrazione è potenza

Il SO nasconde l'enorme complessità dell'hardware dietro interfacce semplici. open("file.csv") attiva decine di strati di software sotto di voi.

2. Le risorse sono limitate e condivise

CPU, memoria, disco, rete: tutto è finito e conteso. Capirlo vi aiuta a scrivere programmi efficienti e diagnosticare problemi.

3. La storia conta

Le scelte degli anni '60 e '70 (Unix, TCP/IP, file system gerarchico) sono ancora le fondamenta del software moderno.
