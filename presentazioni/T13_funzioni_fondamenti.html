Perché le funzioni?

Riuso, astrazione, decomposizione

Il problema

Finora: programmi che scorrono dall'alto verso il basso, in un unico blocco.

Cosa succede quando il codice cresce?
Se dovete calcolare la media in dieci punti diversi del programma, copiate e incollate lo stesso codice dieci volte? E quando trovate un errore, lo correggete in tutti e dieci i posti?

Le funzioni risolvono esattamente questo problema: un blocco di codice con un nome, che potete richiamare ogni volta che serve.

Motivare con un esempio concreto: calcolo della media ripetuto in piu punti.

Tre motivi fondamentali

1. Riuso

Scrivete la logica una volta, la usate ovunque. Un bug? Si corregge in un solo posto.

2. Astrazione

Separare il "cosa" dal "come". calcola_media(voti) dice tutto.

3. Decomposizione

Spezzare un problema complesso in sotto-problemi piccoli e gestibili.

Questi tre concetti sono alla base dell'ingegneria del software. Sottolineare come siano complementari.

Decomposizione funzionale

Un problema complesso si risolve spezzandolo in passi:

Ogni passo diventa una funzione separata. Il codice risultante e modulare, testabile e riutilizzabile.

Breve storia delle subroutine

  • Anni '40 — I pionieri dell'informatica notano blocchi di istruzioni ripetuti
  • Grace Hopper — Promuove l'idea di librerie di subroutine riutilizzabili
  • Anni '60 — "Crisi del software": progetti che sforano tempi e costi
  • Dijkstra — Programmazione strutturata: le funzioni come mattone fondamentale
Da allora, ogni linguaggio di programmazione ha messo le funzioni al centro della propria struttura.

Definire una funzione

La sintassi def con type hints

La prima funzione

def calcola_media(valori: list[float]) -> float:
    """Calcola la media aritmetica di una lista di numeri."""
    somma: float = sum(valori)
    n: int = len(valori)
    return somma / n

Questa funzione:

  • Si chiama calcola_media
  • Accetta un parametro valori di tipo list[float]
  • Restituisce un float
  • Ha una docstring descrittiva
  • Usa return per restituire il risultato

Chiamare la funzione

voti: list[float] = [28.0, 30.0, 25.0, 27.0, 22.0]
media: float = calcola_media(voti)
print(f"Media: {media}")  # Media: 26.4
Definire una funzione non la esegue. La funzione viene eseguita solo quando la chiamate con le parentesi tonde e gli argomenti.

Anatomia di una funzione

def nome_funzione(param1: tipo1, param2: tipo2) -> tipo_ritorno:
    """Docstring: descrizione della funzione."""
    # Corpo della funzione
    risultato = ...
    return risultato
ElementoDescrizione
defParola chiave che introduce la definizione
Nomesnake_case, verbo descrittivo
ParametriVariabili locali con type hints
-> tipoTipo del valore restituito
DocstringDocumentazione della funzione
CorpoBlocco indentato con la logica
returnRestituisce il valore e termina

Perché i type hints?

def calcola_bmi(peso_kg: float, altezza_m: float) -> float:
    """Calcola l'indice di massa corporea."""
    return peso_kg / (altezza_m ** 2)

I type hints non bloccano l'esecuzione se il tipo e sbagliato, ma sono preziosi per:

  1. Documentazione — chi legge capisce subito cosa passare
  2. Errori precoci — strumenti come mypy verificano i tipi prima dell'esecuzione
  3. Autocompletamento — gli editor suggeriscono metodi e attributi corretti

Funzioni che non restituiscono nulla

Se la funzione non restituisce un valore significativo, si annota con -> None:

def stampa_report(titolo: str, dati: list[float]) -> None:
    """Stampa un report formattato a schermo."""
    print(f"=== {titolo} ===")
    for valore in dati:
        print(f"  {valore:.2f}")
-> None comunica esplicitamente: "questa funzione agisce per effetto collaterale (stampa), non produce un risultato da usare."

Parametro vs argomento

# "nome" e "eta" sono PARAMETRI (definizione)
def saluta(nome: str, eta: int) -> str:
    return f"Ciao {nome}, hai {eta} anni!"

# "Anna" e 21 sono ARGOMENTI (chiamata)
messaggio: str = saluta("Anna", 21)
Parametro
La variabile nella definizione. Un "segnaposto" che aspetta un valore.
Argomento
Il valore concreto passato nella chiamata.

Analogia: i parametri sono i campi vuoti di un modulo (Nome: ___). Gli argomenti sono i valori che scrivete.

L'istruzione return

Restituire valori e terminare l'esecuzione

Return: due compiti

return svolge due compiti contemporaneamente:

  1. Restituisce un valore al codice chiamante
  2. Termina immediatamente l'esecuzione della funzione
def quadrato(n: float) -> float:
    return n ** 2

risultato: float = quadrato(5.0)  # risultato = 25.0

Terminazione anticipata

Siccome return termina la funzione, puo essere usato per uscire in anticipo:

def calcola_media_sicura(valori: list[float]) -> float:
    """Calcola la media, restituendo 0.0 se la lista e vuota."""
    if len(valori) == 0:
        return 0.0  # esce subito, il codice sotto non viene eseguito
    return sum(valori) / len(valori)
Pattern "early return": gestire prima i casi speciali, poi il caso normale. Rende il codice piu lineare e leggibile.

Senza return: il valore None

def saluta(nome: str) -> None:
    print(f"Ciao, {nome}!")
    # nessun return esplicito → restituisce None

risultato = saluta("Marco")
print(risultato)  # None
None e un valore speciale di Python che rappresenta "nessun valore". Non e zero, non e la stringa vuota: e proprio l'assenza di valore.

Restituire piu valori con le tuple

def statistiche_base(valori: list[float]) -> tuple[float, float, float]:
    """Restituisce media, minimo e massimo."""
    media: float = sum(valori) / len(valori)
    minimo: float = min(valori)
    massimo: float = max(valori)
    return media, minimo, massimo  # restituisce una tupla
# Spacchettamento dei valori
dati: list[float] = [12.5, 18.3, 9.1, 22.0, 15.7]
m, lo, hi = statistiche_base(dati)
print(f"Media: {m:.1f}, Min: {lo:.1f}, Max: {hi:.1f}")
# Media: 15.5, Min: 9.1, Max: 22.0
Molto comodo per le funzioni statistiche, dove spesso si calcolano piu indicatori in un unico passaggio.

Docstring

Documentare le funzioni

Docstring: formato Google style

def deviazione_standard(valori: list[float], campione: bool = True) -> float:
    """Calcola la deviazione standard di una lista di valori.

    Implementa la formula della deviazione standard, utilizzando
    n-1 al denominatore per la versione campionaria (default)
    oppure n per la versione della popolazione.

    Args:
        valori: lista di valori numerici (almeno 2 elementi).
        campione: se True usa n-1 (Bessel), se False usa n.

    Returns:
        La deviazione standard come float.

    Raises:
        ValueError: se la lista contiene meno di 2 elementi.
    """

Tipi di parametri

Posizionali, con default e keyword

Parametri posizionali

L'ordine degli argomenti corrisponde all'ordine dei parametri:

def intervallo_confidenza(media: float, errore: float) -> tuple[float, float]:
    """Calcola estremi dell'intervallo di confidenza."""
    return media - errore, media + errore

# Gli argomenti sono associati per POSIZIONE
limiti = intervallo_confidenza(25.3, 1.2)
# media=25.3, errore=1.2

Parametri con valore di default

def formatta_numero(valore: float, decimali: int = 2, prefisso: str = "") -> str:
    """Formatta un numero con il numero di decimali specificato."""
    return f"{prefisso}{valore:.{decimali}f}"

print(formatta_numero(3.14159))          # "3.14"
print(formatta_numero(3.14159, 4))       # "3.1416"
print(formatta_numero(3.14159, 3, "€"))  # "€3.142"
Regola: i parametri con default devono venire dopo quelli senza default.
def sbagliata(a: int = 0, b: int) → SyntaxError!

Argomenti keyword

Potete specificare gli argomenti per nome, indipendentemente dall'ordine:

# Argomenti keyword: l'ordine non conta
print(formatta_numero(valore=3.14159, prefisso="€", decimali=3))  # "€3.142"

# Misto: posizionali prima, keyword dopo
print(formatta_numero(3.14159, prefisso="$"))  # "$3.14"
# Cosa significa True?
deviazione_standard(dati, True)
# Si capisce il significato
deviazione_standard(dati, campione=True)

Cenni su *args e **kwargs

*args

Raccoglie argomenti posizionali extra in una tupla:

def somma_tutti(*args: float) -> float:
    totale: float = 0.0
    for valore in args:
        totale += valore
    return totale

print(somma_tutti(1.0, 2.0, 3.0))  # 6.0

**kwargs

Raccoglie argomenti keyword extra in un dizionario:

def stampa_info(nome: str, **kwargs: str) -> None:
    print(f"Nome: {nome}")
    for chiave, valore in kwargs.items():
        print(f"  {chiave}: {valore}")

stampa_info("Anna", corso="Statistica")
Per ora concentratevi su parametri posizionali, default e keyword. Troverete *args e **kwargs nelle librerie.

Il pericolo del default mutabile

Uno dei bug piu insidiosi di Python

Il problema

def aggiungi_voto(voto: int, lista: list[int] = []) -> list[int]:
    """Aggiunge un voto alla lista e la restituisce."""
    lista.append(voto)
    return lista

Sembra ragionevole. Ma guardate cosa succede:

print(aggiungi_voto(28))  # [28]        — fin qui tutto bene
print(aggiungi_voto(30))  # [28, 30]    — aspettavamo [30]!
print(aggiungi_voto(25))  # [28, 30, 25] — la lista "vuota" non è vuota!
Ogni chiamata modifica la stessa lista! Il valore di default [] viene creato una sola volta, quando Python esegue la riga def.

Perché succede?

# L'oggetto default è conservato qui:
print(aggiungi_voto.__defaults__)
# ([28, 30, 25],)  — il default NON è più una lista vuota!

La soluzione: None come default

def aggiungi_voto(
    voto: int,
    lista: list[int] = []
) -> list[int]:
    lista.append(voto)
    return lista
def aggiungi_voto(
    voto: int,
    lista: list[int] | None = None
) -> list[int]:
    if lista is None:
        lista = []  # nuova lista!
    lista.append(voto)
    return lista
Regola d'oro: non usate mai un oggetto mutabile (list, dict, set) come valore di default. Usate None e create l'oggetto dentro la funzione.
Sottolineare che i tipi immutabili (int, float, str, bool, tuple, None) sono sicuri come default.

Scope e namespace

Dove vivono le variabili?

Scope locale

Le variabili create dentro una funzione esistono solo dentro quella funzione:

def calcola_area(base: float, altezza: float) -> float:
    area: float = base * altezza  # variabile LOCALE
    return area

risultato: float = calcola_area(5.0, 3.0)
print(risultato)  # 15.0
print(area)       # NameError: name 'area' is not defined
Vantaggio: potete usare gli stessi nomi di variabile in funzioni diverse senza conflitti. La variabile n in media() e la variabile n in varianza() sono completamente indipendenti.

Scope globale

Variabili definite al livello principale del modulo:

PI: float = 3.14159265  # variabile GLOBALE

def area_cerchio(raggio: float) -> float:
    return PI * raggio ** 2  # può LEGGERE PI

print(area_cerchio(5.0))  # 78.5398...
Una funzione puo leggere le variabili globali, ma non puo modificarle senza una dichiarazione esplicita (global).

global: e perché evitarla

contatore: int = 0

def incrementa() -> None:
    global contatore
    contatore = contatore + 1

incrementa()
print(contatore)  # 1

Dipendenze nascoste, difficile da testare, bug sottili.

def incrementa(contatore: int) -> int:
    return contatore + 1

contatore: int = 0
contatore = incrementa(contatore)
print(contatore)  # 1

Comunicare via parametri e return.

La regola LEGB

Quando Python incontra un nome, lo cerca in quest'ordine:

LivelloSignificatoEsempio
LLocal — scope della funzione correnteVariabili definite nella funzione
EEnclosing — funzioni che racchiudono quella correnteFunzioni annidate
GGlobal — scope del moduloVariabili al livello principale
BBuilt-in — nomi predefiniti di Pythonprint, len, sum

La ricerca si ferma al primo livello in cui il nome viene trovato. Se non e trovato in nessun livello: NameError.

LEGB in azione

x: str = "globale"

def esterna() -> None:
    x: str = "enclosing"

    def interna() -> None:
        x: str = "locale"
        print(x)  # "locale" — trovata in L

    interna()

esterna()
Rimuovendo x = "locale" dalla funzione interna, Python troverebbe x nello scope enclosing. Rimuovendo anche quello, troverebbe quello globale. Senza nessuno dei tre: NameError.

Best practice

Le buone abitudini per scrivere funzioni

Le regole d'oro

  • Funzioni brevi e focalizzate — Una cosa sola, fatta bene. Se superate 20-30 righe, spezzate.
  • Comunicare via parametri e return — Evitate variabili globali. Funzioni pure: output dipende solo dagli input.
  • Type hints sempre — Documentazione vivente, verificabile automaticamente.
  • Nomi significativi — Verbi: calcola_, leggi_, filtra_, conta_, valida_.
  • Docstring per ogni funzione — Anche una sola riga e meglio di niente.

Funzione pura vs impura

# Usa variabile globale
dati: list[float] = [1.0, 2.0, 3.0]

def media_brutta() -> float:
    return sum(dati) / len(dati)
    # dipende dalla variabile
    # globale "dati"
# Riceve i dati come parametro
def media_buona(
    valori: list[float]
) -> float:
    return sum(valori) / len(valori)
    # dipende solo
    # dal parametro

Esempio completo

def analisi_descrittiva(
    valori: list[float],
    nome_variabile: str = "x",
    decimali: int = 2
) -> None:
    """Stampa un'analisi descrittiva di base per una variabile numerica.

    Args:
        valori: lista non vuota di valori numerici.
        nome_variabile: nome della variabile per l'intestazione.
        decimali: numero di cifre decimali nel report.

    Raises:
        ValueError: se la lista e vuota.
    """
    if len(valori) == 0:
        raise ValueError("La lista non puo essere vuota")

    n: int = len(valori)
    media: float = sum(valori) / n

    print(f"=== Analisi descrittiva: {nome_variabile} ===")
    print(f"  n:         {n}")
    print(f"  Media:     {media:.{decimali}f}")
    print(f"  Minimo:    {min(valori):.{decimali}f}")
    print(f"  Massimo:   {max(valori):.{decimali}f}")

Uso dell'esempio

altezze: list[float] = [175.2, 168.0, 182.5, 170.3, 178.9, 165.1, 190.0]
analisi_descrittiva(altezze, nome_variabile="altezza (cm)", decimali=1)
=== Analisi descrittiva: altezza (cm) ===
  n:         7
  Media:     175.7
  Minimo:    165.1
  Massimo:   190.0
Notate come la funzione combini type hints, docstring completa, parametri con default, early return per l'errore e un nome significativo.
