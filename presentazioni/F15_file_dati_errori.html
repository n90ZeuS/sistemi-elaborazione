1. Aprire e chiudere file

open() e il context manager with

Il programma incontra il mondo reale

Finora abbiamo lavorato con dati definiti nel codice.

Nella pratica, i dati arrivano da fuori:

  • File CSV esportati da un database
  • File JSON restituiti da un'API
  • Fogli di calcolo salvati da un collega
Problema: il mondo reale e' disordinato. File inesistenti, encoding sbagliati, righe malformate, colonne mancanti. Un programma robusto deve gestire gli errori.

La funzione open()

Per lavorare con un file, il primo passo e' aprirlo:

# Apertura base — NON fare cosi' (spiegheremo perche')
f = open("dati.txt", "r", encoding="utf-8")
contenuto: str = f.read()
f.close()
ParametroSignificato
filePercorso del file (stringa o Path)
modeModalita' di apertura
encodingCodifica del testo (quasi sempre "utf-8")

Modalita' di apertura

Modalita'SignificatoIl file deve esistere?
"r"Lettura (read) — defaultSi'
"w"Scrittura (write) — sovrascriveNo (lo crea)
"a"Aggiunta (append) — scrive in fondoNo (lo crea)
"x"Creazione esclusiva — errore se esisteNo (lo crea)
Si puo' aggiungere "b" per la modalita' binaria ("rb", "wb"), utile per immagini e file compressi.

Perche' specificare sempre encoding="utf-8"

L'encoding predefinito dipende dal sistema operativo:

  • Windows: spesso "cp1252"
  • macOS / Linux: "utf-8"
Un programma che funziona su macOS potrebbe produrre caratteri incomprensibili su Windows.
Regola: specificare esplicitamente encoding="utf-8" rende il codice portabile e prevedibile.

Il context manager with

Il codice con open()/close() ha un difetto grave:

Se si verifica un errore tra open() e close(), il file resta aperto. I file aperti consumano risorse del sistema operativo. 
# NON fare cosi'
f = open("dati.txt", "r",
         encoding="utf-8")
contenuto = f.read()
f.close()  # Mai raggiunto se errore!
# Il modo CORRETTO
with open("dati.txt", "r",
          encoding="utf-8") as f:
    contenuto = f.read()
# File chiuso automaticamente
Regola senza eccezioni: usate sempre with per aprire i file.

2. Leggere file di testo

Diversi modi per accedere al contenuto

read() — tutto in una volta

with open("romanzo.txt", "r", encoding="utf-8") as f:
    testo: str = f.read()

print(len(testo))  # Numero di caratteri
Attenzione: comodo per file piccoli, ma pericoloso per file grandi. Se il file pesa 4 GB, Python cerchera' di caricare 4 GB in memoria.

readline() e readlines()

readline()

Una riga alla volta:

with open("dati.txt", "r",
         encoding="utf-8") as f:
    prima = f.readline()
    seconda = f.readline()
# Ogni riga include '\n'

readlines()

Tutte le righe in una lista:

with open("dati.txt", "r",
         encoding="utf-8") as f:
    righe = f.readlines()

# .strip() rimuove '\n'
print(righe[0].strip())

Iterazione riga per riga Modo migliore

Per file di qualsiasi dimensione, il modo piu' efficiente e idiomatico:

def conta_righe_non_vuote(percorso: str) -> int:
    """Conta le righe che contengono almeno un carattere non-spazio."""
    conteggio: int = 0
    with open(percorso, "r", encoding="utf-8") as f:
        for riga in f:
            if riga.strip():
                conteggio += 1
    return conteggio
Questo approccio legge una riga alla volta dalla memoria, quindi funziona anche su file enormi.

3. Scrivere file di testo

write(), writelines() e append

write() — scrivere una stringa

def salva_risultato(percorso: str, media: float, n: int) -> None:
    """Salva un riepilogo statistico su file."""
    with open(percorso, "w", encoding="utf-8") as f:
        f.write(f"Numero osservazioni: {n}\n")
        f.write(f"Media: {media:.4f}\n")
Nota: write() non aggiunge automaticamente \n. Dovete inserirlo voi.

writelines() e modalita' append

writelines()

def salva_nomi(percorso: str,
               nomi: list[str]) -> None:
    righe = [nome + "\n"
             for nome in nomi]
    with open(percorso, "w",
              encoding="utf-8") as f:
        f.writelines(righe)

Anche writelines() non aggiunge \n

Append ("a")

def registra_evento(
    percorso: str,
    evento: str
) -> None:
    """Aggiunge un evento al log."""
    with open(percorso, "a",
              encoding="utf-8") as f:
        f.write(f"{evento}\n")

Non cancella il contenuto esistente

4. pathlib

Percorsi cross-platform moderni

Il problema dei percorsi come stringhe

# Funziona solo su Unix,
# si rompe su Windows
percorso = "dati" + "/" + "2024" \
         + "/" + "risultati.csv"
from pathlib import Path

# L'operatore / costruisce percorsi
# in modo cross-platform
percorso = Path("dati") / "2024" \
         / "risultati.csv"
pathlib, introdotto in Python 3.4, offre un'alternativa elegante e sicura alla concatenazione di stringhe per i percorsi.

Operazioni comuni con Path

from pathlib import Path

p: Path = Path("dati") / "esperimento" / "misure.csv"

# Informazioni sul percorso
p.name       # "misure.csv"
p.stem       # "misure"
p.suffix     # ".csv"
p.parent     # dati/esperimento

# Verifica esistenza
p.exists()   # True / False
p.is_file()  # True se e' un file (non una directory)

# Creare directory (anche annidate)
cartella = Path("output") / "grafici"
cartella.mkdir(parents=True, exist_ok=True)

# Elencare file in una directory
for file_csv in Path("dati").glob("*.csv"):
    print(file_csv.name)

Path e open()

Gli oggetti Path funzionano direttamente con open():

from pathlib import Path

percorso: Path = Path("dati") / "studenti.csv"
with open(percorso, "r", encoding="utf-8") as f:
    contenuto: str = f.read()

Oppure, ancora piu' conciso:

from pathlib import Path

percorso: Path = Path("dati") / "studenti.csv"
contenuto: str = percorso.read_text(encoding="utf-8")
Regola: usate pathlib in ogni progetto. Rende il codice piu' leggibile e portabile.

5. Lavorare con file CSV

Il formato standard per i dati tabulari

Il formato CSV

CSV = Comma-Separated Values. Ogni riga e' un record, ogni campo e' separato da un delimitatore.

nome,cognome,voto
Anna,Rossi,28
Marco,Bianchi,25

Leggere con csv.reader

import csv

def leggi_voti(percorso: str) -> list[tuple[str, str, int]]:
    """Legge un CSV di studenti e restituisce una lista di tuple."""
    risultati: list[tuple[str, str, int]] = []
    with open(percorso, "r", encoding="utf-8") as f:
        lettore = csv.reader(f)
        intestazione = next(lettore)  # Salta l'intestazione
        for riga in lettore:
            nome, cognome = riga[0], riga[1]
            voto: int = int(riga[2])
            risultati.append((nome, cognome, voto))
    return risultati

csv.DictReader Piu' leggibile

Usa la prima riga come chiavi, restituisce ogni riga come dizionario:

import csv

def leggi_voti_dict(percorso: str) -> list[dict[str, str]]:
    """Legge un CSV e restituisce una lista di dizionari."""
    with open(percorso, "r", encoding="utf-8") as f:
        lettore = csv.DictReader(f)
        return list(lettore)

# Uso:
studenti = leggi_voti_dict("voti.csv")
for s in studenti:
    print(f"{s['nome']} {s['cognome']}: {s['voto']}")
DictReader rende il codice piu' leggibile: si accede ai campi per nome anziche' per indice numerico.

Il problema del separatore europeo

In Italia la virgola e' il separatore decimale. I CSV esportati da Excel in italiano usano il punto e virgola:

nome;cognome;voto
Anna;Rossi;28
Marco;Bianchi;25

Soluzione: specificare il parametro delimiter:

import csv

with open("dati_italiani.csv", "r", encoding="utf-8") as f:
    lettore = csv.DictReader(f, delimiter=";")
    for riga in lettore:
        print(riga)

Scrivere CSV

import csv

def salva_risultati(percorso: str,
                    dati: list[dict[str, str | float]]) -> None:
    """Salva una lista di dizionari come CSV."""
    if not dati:
        return
    campi: list[str] = list(dati[0].keys())
    with open(percorso, "w", encoding="utf-8", newline="") as f:
        scrittore = csv.DictWriter(f, fieldnames=campi)
        scrittore.writeheader()
        scrittore.writerows(dati)
Il parametro newline="" e' importante su Windows per evitare righe vuote extra nel file.
Anticipazione: con Pandas (Lezione 17), caricare un CSV sara' una singola riga: pd.read_csv("file.csv"). Ma capire il meccanismo e' essenziale per diagnosticare problemi.

6. Lavorare con file JSON

Il formato standard per i dati strutturati

Corrispondenza tipi JSON / Python

JSON = JavaScript Object Notation. Standard per lo scambio dati, specialmente con API web.

JSONPython
object {...}dict
array [...]list
string "..."str
number (intero)int
number (decimale)float
true / falseTrue / False
nullNone

Le quattro funzioni del modulo json

FunzioneInputOutputUso
json.load(f)FileOggetto PythonLeggere da file
json.dump(obj, f)Oggetto PythonFileScrivere su file
json.loads(s)StringaOggetto PythonParsare stringa
json.dumps(obj)Oggetto PythonStringaSerializzare a stringa
Trucco mnemonico: la s finale sta per string.

Leggere e scrivere JSON

Leggere da file

import json
from pathlib import Path

def carica_config(
    percorso: Path
) -> dict:
    with open(percorso, "r",
              encoding="utf-8") as f:
        return json.load(f)

Scrivere su file

import json
from pathlib import Path

def salva_json(
    percorso: Path,
    dati: dict
) -> None:
    with open(percorso, "w",
              encoding="utf-8") as f:
        json.dump(dati, f,
                  indent=2,
                  ensure_ascii=False)
indent=2 produce JSON leggibile. ensure_ascii=False permette caratteri accentati senza escape.

JSON da stringa — utile con le API

Quando si ricevono dati da un'API web, la risposta e' tipicamente una stringa JSON:

import json

risposta_api: str = '{"temperatura": 22.5, "citta": "Roma", "umidita": 65}'
dati: dict = json.loads(risposta_api)
print(f"A {dati['citta']} ci sono {dati['temperatura']}°C")
# A Roma ci sono 22.5°C
Stringa JSON → json.loads() → Oggetto Python
Oggetto Python → json.dumps() → Stringa JSON

File JSON → json.load() → Oggetto Python
Oggetto Python → json.dump() → File JSON

7. Eccezioni e gestione degli errori

try / except / else / finally

Il problema

valore: int = int(input("Inserisci un numero: "))

Cosa succede se l'utente scrive "ciao"?

Python solleva un ValueError e il programma termina bruscamente.

In un programma che analizza migliaia di righe di dati, un singolo valore malformato non dovrebbe far crollare tutto.

try / except

def leggi_intero(prompt: str) -> int:
    """Chiede un intero all'utente, ripetendo in caso di errore."""
    while True:
        try:
            return int(input(prompt))
        except ValueError:
            print("Non e' un numero valido. Riprova.")
1. Python esegue il codice nel blocco try
2. Se nessun errore → il blocco except viene saltato
3. Se si verifica l'eccezione specificata → il controllo passa a except

La gerarchia delle eccezioni

BaseException
├── KeyboardInterrupt      # Ctrl+C
├── SystemExit             # sys.exit()
└── Exception
    ├── ValueError          # Valore sbagliato ("abc" per int())
    ├── TypeError           # Tipo sbagliato (1 + "a")
    ├── KeyError            # Chiave mancante in un dict
    ├── IndexError          # Indice fuori range
    ├── FileNotFoundError   # File non trovato
    ├── PermissionError     # Permessi insufficienti
    ├── ZeroDivisionError   # Divisione per zero
    ├── OSError             # Errori del sistema operativo
    └── ...
KeyboardInterrupt e SystemExit non ereditano da Exception. Catturare Exception non blocca Ctrl+C.

Catturare eccezioni specifiche

# Cattura TUTTO, anche errori
# che non vi aspettavate
try:
    risultato = calcola(dati)
except Exception:
    print("Qualcosa e' andato storto")
    # Ma cosa?!
# Cattura solo gli errori
# prevedibili
try:
    risultato = calcola(dati)
except ValueError as e:
    print(f"Valore non valido: {e}")
except ZeroDivisionError:
    print("Divisione per zero")
Regola: catturate solo le eccezioni che sapete gestire. Catturare eccezioni troppo generiche nasconde i bug.

else e finally

def leggi_dati_sicuro(percorso: str) -> list[str]:
    try:
        f = open(percorso, "r", encoding="utf-8")
    except FileNotFoundError:
        print(f"File non trovato: {percorso}")
        return []
    except PermissionError:
        print(f"Permessi insufficienti per: {percorso}")
        return []
    else:
        # Eseguito SOLO se try e' andato a buon fine
        contenuto: list[str] = f.readlines()
        return contenuto
    finally:
        # Eseguito SEMPRE, errore o no
        print("Tentativo di lettura completato.")
else — eseguito solo se try non ha generato eccezioni
finally — eseguito sempre, utile per cleanup

raise — sollevare eccezioni

A volte siete voi a dover segnalare un errore:

def calcola_media(voti: list[int]) -> float:
    """Calcola la media aritmetica dei voti.

    Raises:
        ValueError: Se la lista e' vuota o contiene voti fuori range.
    """
    if not voti:
        raise ValueError("Impossibile calcolare la media "
                         "di una lista vuota")
    for voto in voti:
        if not 0 <= voto <= 30:
            raise ValueError(f"Voto fuori range: {voto}")
    return sum(voti) / len(voti)
Sollevare eccezioni con messaggi chiari e' un atto di gentilezza verso chi usera' il vostro codice (incluso il vostro se' futuro).

EAFP vs LBYL

Python adotta la filosofia EAFP (Easier to Ask Forgiveness than Permission):

LBYL Non pythonic

# Look Before You Leap
def ottieni_valore(dati, chiave):
    if chiave in dati:
        return dati[chiave]
    else:
        return None

EAFP Pythonic

# Ask Forgiveness
def ottieni_valore(dati, chiave):
    try:
        return dati[chiave]
    except KeyError:
        return None
Perche' EAFP? Evita race condition (il dato potrebbe cambiare tra controllo e accesso) e il caso "normale" (nessun errore) e' piu' veloce.

8. Esempio completo

Leggere un CSV problematico

Lo scenario

Ricevete un file CSV di risposte a un questionario. Il file ha diversi problemi:

  • Potrebbe non esistere
  • Potrebbe usare il separatore ; (CSV europeo)
  • Alcune righe hanno campi mancanti
  • Il campo "eta'" contiene a volte valori non numerici
Questo e' il tipo di problema che si incontra quotidianamente nell'analisi dati.

Soluzione (1/2): apertura e rilevamento

import csv
from pathlib import Path

def carica_risposte(percorso: Path) -> list[dict]:
    risposte: list[dict] = []
    righe_problematiche: int = 0

    try:
        with open(percorso, "r", encoding="utf-8") as f:
            # Rileva il dialetto (separatore) automaticamente
            campione: str = f.read(1024)
            f.seek(0)  # Torna all'inizio

            try:
                dialetto = csv.Sniffer().sniff(
                    campione, delimiters=",;\t"
                )
            except csv.Error:
                dialetto = csv.excel  # Fallback: virgola

            lettore = csv.DictReader(f, dialect=dialetto)
            # ... continua nella slide successiva

Soluzione (2/2): elaborazione righe

            for numero_riga, riga in enumerate(lettore, start=2):
                try:
                    risposta = {
                        "nome": riga.get("nome", "").strip(),
                        "cognome": riga.get("cognome", "").strip(),
                    }
                    # Gestione del campo eta'
                    eta_raw = riga.get("eta", riga.get("età"))
                    if eta_raw and eta_raw.strip():
                        try:
                            risposta["eta"] = int(eta_raw.strip())
                        except ValueError:
                            risposta["eta"] = None  # Non numerico
                    else:

                    if not risposta["nome"]:  # Scarta senza nome
                        righe_problematiche += 1
                        continue
                    risposte.append(risposta)

                except Exception as e:
                    righe_problematiche += 1

Le tre regole da portare con se'

  1. Usate sempre with per aprire i file
  2. Catturate eccezioni specifiche, mai generiche
  3. Usate pathlib per i percorsi: piu' sicuro, leggibile e portabile
open() + with → Lettura/Scrittura sicura
csv / json → Formati dati standard
try / except → Programmi robusti
pathlib → Percorsi portabili
Riepilogare le tre regole chiave. Queste si applicano a qualsiasi progetto Python che interagisce con il filesystem.
