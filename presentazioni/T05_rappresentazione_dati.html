Numeri Interi

Dal binario all'overflow

Rappresentazione in binario

I numeri interi positivi si rappresentano in binario nel modo naturale:

42<sub>10</sub> = 101010<sub>2</sub>

32 + 8 + 2 = 42
Con n bit si rappresentano i numeri da 0 a 2n − 1
• 8 bit → 0 – 255
• 32 bit → 0 – ~4,3 miliardi

Il problema dei numeri negativi

Tre soluzioni storiche:

MetodoIdeaProblema
Modulo e segno Primo bit = segno, resto = valore Due zeri (+0, −0); sottrazione complessa
Complemento a 1 Inversione di tutti i bit Due zeri; complicazioni aritmetiche
Complemento a 2 Inversione + aggiungi 1 Nessuno!

Complemento a due

La soluzione adottata universalmente.

Come funziona

  1. Inverti tutti i bit
  2. Aggiungi 1
La sottrazione diventa un'addizione:
A − B = A + (−B)
Un solo circuito per somme e sottrazioni!

Esempio: −5 su 8 bit

+5 = 00000101
inverti → 11111010
+1 → 11111011 = −5

Con n bit: da −2n−1 a 2n−1 − 1. Con 32 bit: circa ±2,1 miliardi.

Overflow: quando i numeri “traboccano”

Se il risultato di un'operazione è troppo grande per la rappresentazione, i bit in eccesso vengono persi silenziosamente.

Con 8 bit senza segno:
255 + 1 → 11111111 + 1 → 00000000 = 0 (!)

Il contatore “ricomincia da capo”
L'overflow spesso non genera messaggi di errore: il programma continua con un risultato sbagliato.

Il bug dell'anno 2038

Molti sistemi Unix rappresentano il tempo come secondi dal 1/1/1970 in un intero con segno a 32 bit.

  • Il 19 gennaio 2038 alle 03:14:07 UTC il contatore raggiunge il massimo: 2.147.483.647
  • Il valore successivo va in overflow → diventa negativo
  • I sistemi non aggiornati leggeranno: 13 dicembre 1901
Soluzione: passare a interi a 64 bit (già in corso)

L'esplosione dell'Ariane 5 (1996)

370 milioni di dollari distrutti in 37 secondi
  • Software ereditato dal razzo Ariane 4
  • Conversione di velocità orizzontale: float 64 bit → int 16 bit
  • L'Ariane 5 era più veloce dell'Ariane 4: il valore non stava in 16 bit
  • Overflow → errore di navigazione → autodistruzione
Un bug di conversione di tipo. La lezione: mai assumere che un range numerico sia sufficiente senza verificare.

Python: interi a precisione arbitraria

Python non ha limiti sulla dimensione degli interi:

# In C, questo causerebbe overflow con un int a 32 bit:
risultato: int = 2 ** 100
print(risultato)  # 1267650600228229401496703205376

# Python gestisce numeri arbitrariamente grandi:
fattoriale_100: int = 1
for i in range(1, 101):
    fattoriale_100 *= i
print(fattoriale_100)  # un numero con 158 cifre!
Il prezzo: leggera penalità di prestazioni sugli interi molto grandi. Ma per la statistica, la correttezza è più importante della velocità.

Floating point: l'arte dell'approssimazione

Il problema fondamentale

Numeri reali

  • Infiniti
  • Continui
  • Precisione illimitata
→

Bit

  • Finiti
  • Discreti
  • Precisione limitata
La rappresentazione in virgola mobile è sempre un'approssimazione. Comprenderne i limiti è essenziale per chi lavora con dati numerici.

Lo standard IEEE 754

Pubblicato nel 1985: notazione scientifica in binario.

(−1)s × 1,mantissa × 2(esponente − bias)
  • s — bit di segno
  • mantissa — cifre significative
  • esponente — ordine di grandezza
|s| esponente | mantissa |
|1|    11    |    52    | = 64 bit

Formati IEEE 754

FormatoBitSegnoEsponenteMantissaCifre decimali
Single precision321823~7
Double precision6411152~15-16
Python usa la double precision per i suoi float: 64 bit, circa 15-16 cifre decimali di precisione.

Valori speciali

  • +∞ e −∞ — es. float('inf')
  • NaN (Not a Number) — NaN != NaN è True: l'unico valore non uguale a se stesso

Perché 0.1 + 0.2 ≠ 0.3

>>> 0.1 + 0.2
0.30000000000000004
Non è un bug di Python. Succede in qualsiasi linguaggio che usa IEEE 754.

Il motivo: 0,1 in base 10 è un numero periodico in base 2, esattamente come 1/3 = 0,333... in base 10.

0.110 = 0.0001100110011001100...2 (periodico!)

Il computer memorizza l'approssimazione più vicina a 64 bit.

Implicazioni per la statistica

# MAI confrontare float con ==
if media == 0.3:
    print("Uguale")
import math
if math.isclose(media, 0.3,
                rel_tol=1e-9):
    print("Uguale")
  • Errori di accumulazione: sommando milioni di valori, gli errori si accumulano. Può distorcere medie, varianze e test statistici.
  • Pandas e NaN: i valori mancanti nelle colonne numeriche sono NaN IEEE 754. Fondamentale per la pulizia dei dati.

Soluzioni: il modulo decimal

Per calcoli dove serve precisione decimale esatta (es. finanziari):

from decimal import Decimal

# Float: approssimato
print(0.1 + 0.2)              # 0.30000000000000004

# Decimal: esatto!
print(Decimal('0.1') + Decimal('0.2'))  # 0.3
Regola pratica: per la maggior parte dei calcoli statistici i float vanno bene. Usate Decimal per dati finanziari o quando servono confronti esatti.

Il disastro del Patriot (1991)

28 soldati uccisi per un errore di arrotondamento
  • Il sistema misurava il tempo in decimi di secondo su un registro a 24 bit
  • 0,1 in binario è periodico: errore di ~0,000000095 s per ogni tick
  • Dopo 100 ore di funzionamento: errore cumulato di ~0,34 secondi
  • Il Patriot cercò lo Scud in una posizione sbagliata di oltre 600 metri
Un errore di arrotondamento floating point ha causato la morte di 28 persone. Ecco perché questa lezione è importante.
Dhahran, Arabia Saudita, 25 febbraio 1991. Guerra del Golfo. L'errore era noto ma la correzione non era stata distribuita in tempo.

Testo e Codifiche

Da ASCII a Unicode: la torre di Babele digitale

ASCII (1963)

American Standard Code for Information Interchange: 7 bit, 128 simboli.

GruppoCaratteriCodici
Lettere maiuscoleA–Z65–90
Lettere minuscolea–z97–122
Cifre0–948–57
Simboli e punteggiatura! @ # $ % ...vari
Caratteri di controlloa capo, tab, ...0–31
ASCII funzionava perfettamente — per l'inglese. Niente lettere accentate (à, è, ù), n˜, ü, cirillico, giapponese, arabo...

Il caos delle estensioni

Ogni paese creò la propria estensione a 8 bit (256 caratteri):

  • ISO 8859-1 (Latin-1) — Europa occidentale
  • ISO 8859-5 — Cirillico
  • Shift-JIS — Giapponese
  • GB2312 — Cinese semplificato
Risultato: lo stesso byte = un carattere diverso a seconda della codifica. Se un file Shift-JIS viene aperto come Latin-1: mojibake (文字化け, “caratteri trasformati”).

Unicode

Il progetto (1991-oggi) di codificare ogni carattere di ogni sistema di scrittura umano.

  • Oltre 150.000 caratteri da 161 scritture diverse
  • Ogni carattere ha un code point univoco: U+XXXX
CarattereCode pointNome
AU+0041LATIN CAPITAL LETTER A
àU+00E0LATIN SMALL LETTER A WITH GRAVE

Ma Unicode è un catalogo, non una codifica. Come si memorizzano i code point in byte?

UTF-8: la codifica che ha vinto

Inventata nel 1992 da Ken Thompson e Rob Pike su una tovaglietta di carta a cena.

Byte usatiRange code pointEsempio
1U+0000 – U+007FCaratteri ASCII (A, B, 1, 2...)
2U+0080 – U+07FFAccenti, cirillico (à, è, ü...)
3U+0800 – U+FFFFCJK, arabo, thai...

Compatibile con ASCII • Lunghezza variabile (efficiente) • Auto-sincronizzante
Oltre il 97% delle pagine web usa UTF-8. Standard de facto di internet.

Python 3 e Unicode

Le stringhe str sono Unicode nativamente:

nome: str = "François"
citta: str = "東京"       # Tokyo in giapponese
print(len(citta))          # 2 (ogni carattere conta 1)
# Codifica sbagliata
with open("dati.csv",
          encoding="utf-8") as f:
    f.read()
# UnicodeDecodeError!
# Codifica corretta
with open("dati.csv",
          encoding="latin-1") as f:
    f.read()
# Funziona!
Consiglio: salvate sempre in UTF-8. Per file di terze parti, provate latin-1 o cp1252.

Immagini, Audio e Video

Digitalizzare il mondo analogico

Immagini digitali

Un'immagine è una griglia di pixel, ogni pixel è un colore rappresentato da numeri.

Modello RGB

  • 3 canali: Red Green Blue
  • 8 bit/canale → 256 livelli
  • 24 bit/pixel → 16,7 milioni di colori

Parametri chiave

  • Risoluzione: numero di pixel (es. 1920×1080)
  • Profondità: bit per canale (8, 16, 32)
Intuizione: un'immagine RGB 1920×1080 è un array 3D di dimensione 1080 × 1920 × 3. Analizzare immagini = algebra lineare con NumPy.

Formati immagine

FormatoCompressioneQualitàDimensione (1920×1080)
BMP Nessuna Originale ~6 MB
JPEG Con perdita (lossy) Degradata ad ogni salvataggio ~0,3–1 MB
PNG Senza perdita (lossless) Identica all'originale ~1–3 MB
Attenzione: non salvate ripetutamente in JPEG un'immagine su cui state lavorando. Ogni salvataggio perde qualità!

Audio e video digitale

Audio

Un suono è un'onda continua. Si campiona a intervalli regolari.

Teorema di Nyquist-Shannon:
frequenza di campionamento ≥ 2 × frequenza massima

Orecchio: ~20.000 Hz
CD audio: 44.100 Hz, 16 bit/campione

Video

Sequenza di frame + traccia audio.

Full HD non compresso a 30 fps:

6 MB × 30 = 180 MB/s
1 ora = ~650 GB

Codec (H.264, H.265, AV1) sfruttano ridondanza tra frame.

Perché è rilevante per la statistica?

I dati moderni non sono solo tabelle di numeri:

  • Immagini mediche (radiografie, risonanze)
  • Dati satellitari e telerilevamento
  • Analisi del parlato e del linguaggio
  • Riconoscimento di pattern in video
Comprendere la natura digitale di questi dati — campionamento, quantizzazione, compressione — è il primo passo per analizzarli correttamente.

Formati di Dati Strutturati

CSV, JSON, Parquet e oltre

CSV (Comma-Separated Values)

Il formato più semplice e diffuso in statistica:

nome,cognome,voto,data_esame
Mario,Rossi,28,2024-01-15
Anna,Bianchi,30,2024-01-15

Vantaggi

  • Universale e leggibile
  • Supportato ovunque

Problemi

  • Nessun tipo di dato (tutto è testo)
  • Ambiguità con i separatori
  • Nessuno standard rigido
Trappola europea: in Italia il separatore decimale è la virgola (3,14). Per evitare conflitti, si usa il punto e virgola come separatore di campo. Verificate sempre!

JSON (JavaScript Object Notation)

Formato standard per dati gerarchici e API web:

{
    "nome": "Mario",
    "cognome": "Rossi",
    "voti": [28, 30, 27],
    "indirizzo": {
        "citta": "Milano",
        "cap": "20100"
    }
}
Supporta tipi di dato: stringhe, numeri, booleani, null, array, oggetti annidati. Leggibile da umani e macchine.

XML ed Excel

XML

<studente>
  <nome>Mario</nome>
  <cognome>Rossi</cognome>
  <voto>28</voto>
</studente>

Verboso ma espressivo. Diffuso nella PA e servizi SOAP.

Excel (.xlsx)

Onnipresente ma problematico per uso scientifico:

  • Conversioni automatiche non richieste
  • Limite: 1.048.576 righe
  • Formato binario proprietario

Excel e i geni rinominati

Un software ha costretto la scienza a cambiare i nomi dei geni.
  • Excel convertiva automaticamente nomi di geni come MARCH1 e SEPT2 in date (1 marzo, 2 settembre)
  • Il problema era così diffuso che nel 2020 l'organizzazione HUGO Gene Nomenclature Committee ha rinominato 27 geni umani
Lezione: mai usare Excel per il lavoro scientifico serio. Usate formati che non “aiutano” senza chiedere.

Formati binari per grandi dataset

Quando CSV diventa lento (milioni di righe, gigabyte):

FormatoStrutturaUso tipico
Parquet Colonnare, compresso, tipi nativi Grandi dataset con Pandas
HDF5 Gerarchico Fisica, astronomia, bioinformatica
Feather Ottimizzato per DataFrame Scambio veloce Python ↔ R
Regola pratica: CSV per portabilità, Parquet per prestazioni, JSON per dati gerarchici. Mai Excel per lavoro scientifico.

Riepilogo

Idea fondamentale: la rappresentazione digitale dei dati è sempre un'approssimazione.

Numeri

  • Interi: complemento a 2, overflow
  • Float: IEEE 754, errori di arrotondamento

Testo e media

  • Testo: ASCII → Unicode/UTF-8
  • Immagini/audio: campionamento e compressione
Tre regole per lo statistico:
  1. Non fidatevi ciecamente dei numeri — solo 15-16 cifre sono significative
  2. Conoscete i vostri dati — encoding, tipi, NaN, conversioni implicite
  3. Scegliete il formato giusto — CSV, Parquet, JSON, mai Excel per la scienza
